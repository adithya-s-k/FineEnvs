## Small models across many harnesses

Everything so far has been other people's evidence. This is where the article stops citing and starts
running things.

The question is narrow on purpose. Take a small open model, one that a person with a modest GPU
budget could actually train, and ask whether it can be made competent at a real agentic task. Then
ask the harder question underneath it: does that competence belong to the model, or to the harness it
was trained in? The introduction showed several labs answering that question the expensive way, by
shipping a model and discovering later that it did not travel. The point of the next few sections is
to answer it deliberately, in the open, with everything reproducible.

The domain is data analysis. A model is dropped into a container with a dataset it has never seen, a
question in plain English, and a Python environment, and it has to work out the answer. That choice
is not arbitrary, and it is worth saying why, because the domain does most of the work in making an
RL experiment either honest or useless.

It is **multi-turn but bounded**. The model loads a file, looks at the shape of it, tries something,
reads the result, corrects itself. That is genuine agentic behaviour, several tool calls deep, and it
still terminates in a minute or two rather than an hour. Long-horizon software engineering is more
impressive and far more expensive to iterate on.

It is **verifiable**. Most questions have one right answer, and a grader can check it without asking
a language model for an opinion. That keeps the reward honest, which matters more than it sounds:
the previous guide's chapter on reward hacking exists because graders that are easy to satisfy get
satisfied in ways nobody intended.

And it is **not saturated**. Small models are genuinely bad at this to begin with, which leaves room
for training to show up as something other than noise.

### The Data Agent dataset

The tasks are built from the [jupyter-agent
dataset](https://huggingface.co/datasets/jupyter-agent/jupyter-agent-dataset), which pairs real
Kaggle notebooks with the questions they answer. Each usable question becomes one Harbor task: the
question becomes the instruction, the notebook's own answer becomes the gold answer, the Kaggle
dataset it depended on becomes a container that pulls that data in at start-up, and a grader is
generated and then tested against the known answer.

That last step is the one that takes the time. A question is only useful for training if the grader
actually fires correctly on the known-good answer, so tasks that fail verification are dropped rather
than shipped with a reward function nobody checked. What survives is two suites:

| Suite | Tasks | Purpose |
|---|---|---|
| [`data_agent_rl_environment_train`](https://huggingface.co/datasets/AdithyaSK/data_agent_rl_environment_train) | 2,238 | training |
| [`data_agent_rl_environment_eval`](https://huggingface.co/datasets/AdithyaSK/data_agent_rl_environment_eval) | 366 | held out, never trained on |

Each task carries an assigned difficulty from L1 to L5, and the distribution is worth looking at
honestly rather than presenting as a neat curve. L1 and L2 together are 68 percent of the suite: one
line of pandas, or a filter and a groupby. L5, meaning genuinely hard multi-step work, is eleven
tasks out of 2,238. That shape is a real limitation of building tasks from public notebooks, and it
sets a ceiling on what any result here can claim. A model that improves on this suite has learned to
do short data-analysis tasks reliably. It has not learned to do research.

There are also three variants of the training suite, each built to answer a question the main run
raised: a
[100-task subset](https://huggingface.co/datasets/AdithyaSK/data_agent_rl_environment_train_subset_100)
for fast iteration, a
[multi-reward](https://huggingface.co/datasets/AdithyaSK/data_agent_rl_environment_train_multireward)
variant, and a
[difficulty-ranked](https://huggingface.co/datasets/AdithyaSK/data_agent_rl_environment_train_difficulty_ranked)
ordering for curriculum experiments. The ablations in a later section use these.
